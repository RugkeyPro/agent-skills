# Nature-Writer Skill 重构方案

> 目标：在不丢失任何现有知识的前提下，把这个 skill 从"一篇 437 行的长文档"改造成"薄路由 + 按需加载的参考库"，符合 skill 的渐进式披露（progressive disclosure）原则，更易触发、更省上下文、更好维护。

---

## 一、现状诊断

当前文件结构：

```
Nature-Writer/
├── SKILL.md              437 行   ← 触发时全量进入上下文
├── Nature-essays.md     ~2150 行 / 21 篇论文   ← 无索引的单一大文件
├── references/
│   ├── phrase-bank.md    340 行
│   └── section-templates.md 254 行
└── evals/evals.json      3 个用例（全是"生成"类）
```

核心问题（按严重度排序）：

**1. SKILL.md 过长且全量加载。** 渐进式披露的原则是：SKILL.md 只放"何时用 + 工作流 + 路由"，细节放进 references 按需读取。当前 437 行里大量是查表型细节（动词替换表、各刊术语、检查清单、句法库），这些每次触发都被塞进上下文，挤占预算却未必用得上。

**2. 严重的三处重复。** 同一套知识在多个文件里各写了一遍，维护时要改 3–4 处：

| 知识点 | 出现位置 |
|--------|---------|
| CEI（Claim-Evidence-Interpretation）模型 | SKILL.md §一(Results)、§三(专章)、phrase-bank §十一、templates "CEI 模板" |
| 五种"研究缺口"句式 | SKILL.md §一(Intro) + §五、phrase-bank §二 + §十二 |
| 局限性段落结构 | SKILL.md §一(Discussion) + §七、phrase-bank §十三、templates "局限性(3种)" |
| 各子刊特点（NCC/NS/NEE/NG） | SKILL.md §二、phrase-bank §十、templates 散落各处 |

**3. 工作流被埋在最底部。** 真正的"怎么干"（判断期刊→判断章节→对照改写）在第 426 行的"使用说明"。模型要读完 425 行才看到操作步骤，顺序是反的。

**4. 组织维度不一致。** 有的地方按"章节"组织（§一 IMRaD），有的按"期刊"组织（§二 子刊），同一信息两套切法交叉，读者（模型）难以定位。

**5. 语料库无法被有效使用。** `Nature-essays.md` 含 21 篇真实论文，是这个 skill 最宝贵的资产，但它是一个无索引大文件，且 SKILL.md 没说清"什么时候、怎么用它当范本"。模型要么整篇读（浪费），要么忽略（浪费资产）。

**6. 没有确定性校验。** skill 里有几条硬规则（全文禁破折号、缩写首次全称、单位紧跟数字、Methods 不出现结果），这些完全可以用一个小脚本机械检查，比让模型"自检"更可靠。

**7. evals 覆盖面窄。** 3 个用例全是"从零生成"。但 description 主打的"润色一段话"、"中文草稿改写成顶刊英文"、"这个 Introduction 写得怎么样（批评/打分）"三类高频场景一个都没测。

---

## 二、目标架构

```
Nature-Writer/
├── SKILL.md                  ~160 行：触发说明 + 三种任务模式路由 + 十条核心原则 + 工作流
├── references/
│   ├── journals.md           各期刊结构规格（正刊/NC/NCC/NS/NEE/NG/Science）——按期刊组织
│   ├── sections.md           各章节写法（Abstract/Intro/Methods/Results/Discussion）+ CEI 模型——按章节组织
│   ├── phrase-bank.md        去重后的功能短语查找库（保留，删掉与 sections 重复的解说）
│   ├── templates.md          填空式段落模板（原 section-templates，去重）
│   └── style-rules.md        时态/标点/语态/数字/中式表达替换/检查清单——硬规则集中地
├── corpus/
│   ├── INDEX.md              21 篇论文索引表（期刊·主题·方法·可示范的写作点）
│   └── *.md                  按论文拆分（或保留单文件但加锚点索引）
├── scripts/
│   └── lint.py               机械校验：破折号、词数、缩写首用、Methods 含结果词、单位格式
└── evals/
    └── evals.json            扩到 6–8 个：+润色 +中译英改写 +批评打分 +Methods +正刊Main
```

设计主线：**SKILL.md 当薄路由，三类参考维度各归其位（按期刊 / 按章节 / 按规则），语料加索引，硬规则交给脚本。** 模型每次只加载它当前任务真正需要的那 1–2 个 reference。

## 三、文件职责与迁移映射

> 原则：**所有现有内容都有去处，不删知识，只去重、归位、加索引。**

### SKILL.md（瘦身到约 160 行）
保留并前置：
- frontmatter（description 略收紧，见 §五）
- **任务模式路由**（新增，最关键）：开篇即区分三种来意，并指向对应 reference
  - 模式 A 生成：用户给背景+数据，要某章节 → 读 `sections.md` + `templates.md` + 对应期刊段 `journals.md`
  - 模式 B 润色/改写：用户给已有文字（含中文草稿）→ 读 `style-rules.md`（中式表达替换、时态、标点）+ `phrase-bank.md`
  - 模式 C 批评/诊断："这段写得怎么样" → 对照 `style-rules.md` 的检查清单逐条点评
- §六"十条核心原则"（保留，这是高价值的浓缩纲领）
- 末尾"工作流五步"上移到显著位置
迁出：§零/§一/§二/§四/§五/§七/§八/§九 的细节 → 拆到下列 references。

### references/journals.md（新建，吸收 SKILL.md §零 + §二 + §九）
按期刊一节，每节含：结构规格（标题/Abstract 词数/IMRaD 切法/Methods 位置/参考文献量）+ 该刊特有叙事模式 + 关键术语。把原 §零的对比表、§二的子刊指南、§九的 Science 差异全部归并到这里，**消除"按期刊"信息的散落**。

### references/sections.md（新建，吸收 SKILL.md §一 + §三）
按章节一节：Abstract 四句式、Introduction 漏斗六段 + 五种缺口句、Methods 硬规则、Results 的 CEI、Discussion 段落逻辑 + 局限性结构。**CEI 模型在此处定义一次**，其余地方只引用不重写。

### references/style-rules.md（新建，吸收 SKILL.md §四 + §五 + §七 + §八）
集中所有"句子层"规则：时态表、标点（禁破折号）、语态、数字单位、强力动词替换表、中式表达→顶刊表达表、各章节检查清单。模式 B/C 主要读这一个文件。

### references/phrase-bank.md（保留，去重）
删除与 sections.md / journals.md 重复的解说性文字（如 §十一 CEI 解释、§十二 缺口分类解释——这些归 sections.md），只保留纯"可直接套用的句式条目"。它的定位收窄为**查找式句库**。

### references/templates.md（原 section-templates.md，去重）
保留填空模板。删掉与 phrase-bank 重复的零散句子，专注"整段骨架"。

### corpus/INDEX.md（新建）+ 语料拆分
为 21 篇论文建索引表：

| 文件 | 期刊 | 主题 | 方法 | 可示范的写作点 |
|------|------|------|------|---------------|
| coilia-habitat.md | 区域期刊 | 鱼类生境 | MaxEnt | Abstract 模板B、Methods 复现细节 |
| river-plastic.md | Nature | 河流塑料 | 全球模型 | 正刊叙事型 Abstract、量化收尾 |
| zooplankton-shift.md | NCC | 浮游动物 | trait-based | 因果链、"支持/挑战预期"句法 |
| … | | | | |

SKILL.md 在"需要范本时"指向 INDEX，模型据此**只读 1 篇相关论文**而非整个 2150 行文件。拆分可选（也可保留单文件+行锚点），但索引必建。

### scripts/lint.py（新建）
输入一段/一篇文本，机械检查并报告：
- 是否含 em dash `—`（硬规则：禁用）
- Abstract/正文词数是否超目标刊上限
- 缩写是否首次出现即给全称
- Methods 段是否混入结果性词汇（found/showed/significant…）
- 数字与单位是否紧贴、范围用 en dash `–`

这把"模型自检"变成"脚本判定"，更稳，且每次调用复用。

## 四、关键设计决策

1. **三维不交叉**：期刊维度只进 `journals.md`，章节维度只进 `sections.md`，句子规则只进 `style-rules.md`。任何一条知识只存一处，引用而非复制。这是解决"改一处要改四处"的根治办法。

2. **路由前置**：模型读 SKILL.md 头部就知道"用户是要生成 / 润色 / 批评"，并直接被导向该读哪个 reference，不必把全部细节背在身上。这同时改善**触发后效率**和**上下文占用**。

3. **语料从负担变资产**：加索引后，范本可被精准、低成本地调用，这是当前设计完全没发挥的价值点。

4. **硬规则脚本化**：禁破折号等是 0/1 判定，交给 `lint.py`，作为生成后的收尾校验步骤写进工作流。

5. **保留十条核心原则**：它是全 skill 唯一不该被拆走的"纲"，留在 SKILL.md 当锚。

## 五、description 收紧（提升触发精度）

当前 description 偏长且把所有子刊名都列出。建议保留"即使只说'帮我润色一下这段话'也要触发"这类反欠触发表述（有效），但压缩期刊枚举。重构后建议在 skill-creator 的描述优化环节用 20 条 trigger eval（含近义负例，如"帮我把这段中文翻译成英文邮件"应**不**触发）跑一轮，量化定稿。

---

## 六、evals 扩展（从 3 个到 6–8 个）

现有 3 个生成类保留，新增覆盖 description 主打但未测的场景：

- **润色**：给一段中式英文 Results，要求改成 NC 风格 → 验证 CEI、时态、强力动词替换
- **中译英改写**：给中文 Discussion 草稿 → 验证学术英文风格 + 禁破折号 + 局限性结构
- **批评/诊断**："这个 Introduction 写得怎么样？"给一段有缺陷的引言 → 验证能否点出缺口句缺失、topic sentence 缺失等
- **Methods**：给参数清单要写 Methods → 验证被动语态、不含结果、复现细节
- **正刊 Main**：给数据要写无小节标题的正刊主体 → 验证正刊 vs 子刊结构差异

每个 eval 配可机械判定的 assertion（词数、是否含破折号、是否含"Here we"、是否含定量数字等），便于用 `lint.py` 和 grader 自动打分。

## 七、分步执行计划

1. **备份**：`cp -r Nature-Writer Nature-Writer-snapshot/`（作为评测基线，对比新旧版本）。
2. **建骨架**：创建 `references/journals.md`、`sections.md`、`style-rules.md`、`corpus/INDEX.md`、`scripts/lint.py`。
3. **搬运去重**：按 §三 映射把 SKILL.md 的 §零~§九 内容迁出、合并、删重复；phrase-bank / templates 去重。
4. **重写 SKILL.md**：瘦身到约 160 行，前置路由与工作流。
5. **建语料索引**（拆分可选）。
6. **写 lint.py** 并在工作流里加"生成后校验"步骤。
7. **扩 evals** 到 6–8 个并补 assertion。
8. **跑评测**：用 skill-creator 的流程，新版 vs 快照基线，生成 eval viewer 给你逐例审阅。
9. **据反馈迭代**，满意后做 description 优化、打包成 `.skill`。

## 八、预期收益

- SKILL.md 触发时上下文占用从 ~437 行降到 ~160 行，细节按需加载。
- 单一知识源，维护成本从"改 4 处"降到"改 1 处"。
- 21 篇语料从沉睡资产变为可精准调用的范本。
- 硬规则由脚本兜底，输出一致性提升。
- 评测覆盖润色/翻译/批评三类真实高频场景，迭代有据可依。
- 知识零丢失：所有现有内容都被保留并重新归位。
