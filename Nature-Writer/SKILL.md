# Nature-Writer

辅助研究者产出 Nature 系列顶刊水准的英文学术论文。本文件是**路由与工作流**；细节按需读取对应参考文件，不必一次全部加载。

## 参考文件地图（按需读取）

| 文件 | 何时读 |
|------|--------|
| `references/journals.md` | 确定目标刊的结构骨架（正刊/NC/NCC/NS/NEE/NG/Science） |
| `references/sections.md` | 写某一章节的方法论 + CEI 段落模型（章节写法的权威来源） |
| `references/style-rules.md` | 时态/标点/语态/数字/中式表达替换/检查清单（润色与诊断主用） |
| `references/phrase-bank.md` | 查找现成英文单句 |
| `references/section-templates.md` | 需要整段填空骨架 |
| `corpus/INDEX.md` | 需要一篇真实论文当范本时，先查索引再定位单篇 |
| `scripts/lint.py` | 生成/润色后机械校验硬规则（破折号、词数、缩写、Methods 混结果等） |

## 工作流

每次接到任务，先判断**任务模式**，再判断**目标刊**与**章节**，然后只加载需要的参考文件。

### 第一步：判断任务模式

- **模式 A — 生成**：用户给研究背景/数据，要从零写某章节。
  路径：定目标刊（`journals.md`）→ 读该章节写法（`sections.md`）→ 取整段骨架（`section-templates.md`）与句式（`phrase-bank.md`）→ 需要范本时查 `corpus/INDEX.md` 定位单篇 → 起草 → 用 `lint.py` 收尾校验。

- **模式 B — 润色/改写（含中译英）**：用户给已有英文或中文文字，要改成顶刊风格。
  路径：主读 `style-rules.md`（中式表达替换、时态、标点、强力动词）+ `phrase-bank.md` → 逐句改写，保留原意 → `lint.py` 校验 → 简述改了哪些方面。

- **模式 C — 批评/诊断**：用户问"这段写得怎么样"。
  路径：用 `style-rules.md` 末尾的对应章节检查清单逐条点评，指出最该优先修的问题（缺口句缺失、topic sentence 缺失、CEI 不完整、时态错误、定性代替定量、中式表达、逻辑断裂），给出可操作的修改方向，必要时示范重写关键句。

### 第二步：判断目标刊与章节

目标刊决定结构骨架（有无 Introduction 标题、Results/Discussion 是否合并、Abstract 词数、Methods 位置），见 `journals.md` 速查表。章节决定具体写法，见 `sections.md`。两者都不确定时，先问用户目标期刊与章节，再动笔。

### 第三步：起草 / 修改的优先级

优先修正这些高频硬伤：缺口句（P3）缺失、CEI 段落模型不完整、时态错误（结果用过去时、图表与结论用现在时）、定性描述替代定量结论、中式表达、段落逻辑不连贯、Methods 混入结果。

### 第四步：收尾校验

生成或润色后，对照 `style-rules.md` 的检查清单自检；可机械判定的硬规则交给 `scripts/lint.py`（用法 `python scripts/lint.py --section <章节> <文件>`，能扫出破折号、超词数、缩写首用、Methods 混结果、ASCII 数值范围、过度确定措辞）。

## 十条核心原则

1. **量化一切**：每个关键结论都需数字支撑，不用定性代替定量。
2. **开门见山**：每段首句即中心句（topic sentence）。
3. **逻辑链完整**：问题→方法→结果→机制→意义，不跳跃。
4. **证据-主张匹配**：每个主张紧跟支撑证据（数据或引用）。
5. **承认局限**：Discussion 必须有诚实、具体的 limitations，这是顶刊标志。
6. **精准用词**：一词不多不少，名词短语压缩篇幅。
7. **全球/大尺度视角**：区域研究也要联系全球趋势。
8. **图表自说话**：引用图表时解释科学含义，不重复图注。
9. **不确定性敏感**：报告不确定性和/或敏感性分析；缺失则提示补充。
10. **短句为主**：拆分过长复合句；**全文禁止任何形式的破折号（em dash）**。

## 通用准则

- **保留原意**：改善语言时忠实于作者的原始科学表述，不臆造数据或结论。
- **缺信息就问**：目标刊、章节、词数限制不明时，先确认再动笔，避免返工。
- **修改说明可选**：根据用户需要，简要说明改了哪些方面。
